# SpeechBridge 발표자 노트

실제 앱 캡처와 합성 시연 데이터를 사용합니다. 약 8–10분 구성이며 실기기 녹음 성공을 주장하지 않습니다.

## 1. VOICE → ACTION

SpeechBridge는 대화를 번역한 뒤 기록과 할 일로 연결하는 앱입니다. 음성 중심 UI이며 Android와 iOS 공통 구현입니다. 오늘 보여주는 화면은 실제 iOS 시뮬레이터에서 만든 가상 시연 기록입니다. 실제 마이크와 휴대전화 검증은 보류 상태임을 먼저 분명히 설명합니다.

## 2. 번역한 대화, 그다음은 어디에 남을까요?

회의나 일상 대화에서는 번역된 문장만큼 맥락과 후속 행동이 중요합니다. 번역 내용을 다른 메모 앱에 옮기고 할 일을 다시 작성하는 흐름을 줄이는 것이 목표입니다. 별도의 사용자 조사 수치나 시간 절감률을 주장하지 않습니다.

## 3. 입력은 단순하게. 번역은 이어서.

대화 화면의 중심은 큰 마이크 버튼입니다. 한국어·영어·일본어를 지원하며, 구현된 음성 파이프라인은 발화 완료 후 처리합니다. 키보드는 보조 입력입니다. 오른쪽 실제 결과는 영어 문장을 직접 입력한 뒤 로컬 AI가 번역한 사례이며 음성 인식 결과라고 설명하지 않습니다.

## 4. 대화가 끝나면, 처음 한 번 AI가 정리합니다.

대화 종료 시 서버에 저장되는 작업이 제목·일상 또는 업무 분류·요약을 생성합니다. 작업 상태는 DB에 남기므로 서버가 재시작되어도 이어갈 수 있습니다. 화면의 demo reviewed는 자동 제목을 사람이 수정한 결과입니다. 이후 제목·분류·요약 편집은 사용자에게 맡깁니다.

## 5. AI가 찾고, 사용자가 근거를 확인합니다.

AI가 만든 요청·결정 후보에는 참조 원문이 연결됩니다. 사용자가 근거를 읽고 내용을 검토한 뒤 할 일로 등록하거나 완료할 수 있습니다. 검토 표시는 상대방의 동의나 업무 수락을 뜻하지 않습니다. 준비된 수동 예시와 실제 AI 추출 항목을 구분해서 보여줍니다.

## 6. AI는 Mac에서, 사용자 데이터는 PostgreSQL에.

앱은 Kotlin Multiplatform과 Compose로 구현했습니다. 회원 인증된 HTTPS 요청을 Mac 서버가 받아 로컬 모델로 처리합니다. 번역은 TranslateGemma, 요약과 추출은 Gemma 계열이며 유료 API fallback은 없습니다. PostgreSQL에 계정별 원본을 저장하고, 기기에는 암호화된 미전송 변경만 남깁니다. 아래는 주요 흐름을 단순화한 구조입니다.

## 7. 한 모델에 모두 맡기지 않고, 역할을 나눴습니다.

모델을 새로 학습한 것이 아니라 공개 가중치를 Mac에서 실행합니다. STT는 Nemotron 3.5 ASR Streaming 0.6B Q8 GGUF, 번역은 TranslateGemma 12B Q4_K_M, 정리는 Gemma 4 12B IT QAT, TTS는 Qwen3-TTS-12Hz-0.6B-CustomVoice의 MLX bf16 변환본입니다. B는 이름의 규모 표기이며 파일 크기나 메모리 용량과 다릅니다. 구현·버전·선정 근거: docs/MODEL_SELECTION.md, docs/LOCAL_AI_RESULTS.md, docs/LOCAL_VOICE_RESULTS.md.

## 8. 의미를 보존하고, 근거를 확인할 수 있도록.

번역에는 번역 전용 모델인 TranslateGemma 12B Q4_K_M을 사용합니다. 업무 대화의 수량·시간·부정 표현과 이름을 보존하는 것이 선정 기준이며, 현재 Mac에서 필요한 세 언어의 예제 실행을 확인했습니다. 제목·분류·요약·할 일 후보에는 Gemma 4 12B IT QAT를 사용합니다. JSON mode로 구조화된 결과를 받고 서버가 원문 ID와 인용 근거를 검증할 수 있어 기록 기능에 적합합니다. 최초 정리는 AI가 담당하고 이후 편집은 사용자에게 맡깁니다. 이는 현재 프로젝트 조건에 맞춘 선정이며 일반 정확도나 모든 후보 대비 우위를 보장하지 않습니다. 선정 근거 문서: docs/MODEL_SELECTION.md.

## 9. 세 언어와 Mac 실행 조건을 충족하는 음성 모델.

STT는 필요한 한국어·영어·일본어와 Metal 런타임을 확인해 선택했습니다. 합성 샘플에서 세 언어의 전사를 확인했지만 일본어 고유명사 오류가 남아 있습니다. TTS는 Qwen 공식 카드에 한·영·일 지원이 명시되어 있고 현재 Mac의 MLX 변환본에서 PCM 생성이 성공했습니다. 고정 음색을 사용하며 사용자 음성 복제를 요구하지 않습니다. 음성 모델의 실사용 품질과 고유명사 인식은 추가 검증이 필요하며, TTS 생성에는 준비 시간이 있습니다. 실제 마이크·사람 청취는 미검증입니다. 공식 근거: https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b , https://github.com/NVIDIA/NeMo-Speech.cpp/blob/v0.2.0/docs/install.md , https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice . 로컬 결과: docs/LOCAL_VOICE_RESULTS.md 및 .ecc/benchmarks/tts-member-https.json.

## 10. 연결이 끊겨도, 변경 내용을 잃지 않도록.

연결이 끊기면 대기 내용만 Android 보안 저장소 또는 iOS Keychain에 보관합니다. 서버가 응답하면 대기 항목을 제거하고 mutation ID로 재전송 중복을 막습니다. 다중 기기 충돌은 무조건 덮어쓰지 않습니다. 백업은 검증 후 복원하며, 계정 삭제 이력을 다시 적용합니다. 실제 오프라인 UI에서 전송 대기 1건이 재연결 후 자동 저장 완료로 바뀌는 것을 확인했습니다.

## 11. 동작한 것과, 아직 확인하지 않은 것을 구분합니다.

핵심 시연 흐름을 직접 앱에서 조작하고, 최종 저장 결과를 PostgreSQL과 대조했습니다. 서버 테스트와 Android Host 및 iOS 시뮬레이터 회귀를 실행했습니다. 테스트 수가 제품 전체 커버리지나 실사용 정확도를 뜻하지는 않습니다. 음성은 합성 샘플로 파이프라인을 검사했고 실제 마이크, 휴대전화, 청취는 보류 상태입니다. 최신 수치는 저장소의 PRE_RELEASE 문서에서 확인합니다.

## 12. 한 문장이 기록과 할 일이 되는 과정.

시연 시작은 프로젝트의 Demo.command입니다. Mac 서버가 실행되고 iOS 시뮬레이터는 시연 계정에 로그인되어 있습니다. 음성 시연이 보류된 자리에서는 키보드 보조 입력으로 표시한 문장을 입력합니다. 원문과 번역을 보여 준 뒤 종료하고 요약을 기다립니다. 할 일 추출 후 근거를 검토하고 완료합니다. 네트워크 장애 시 준비된 기록으로 설명하되 AI가 새로 처리한 것처럼 말하지 않습니다.

## 13. SPEECHBRIDGE

마무리입니다. SpeechBridge는 번역에서 멈추지 않고 대화의 맥락과 실행할 일을 연결합니다. 전체 소스, 시연 절차, 검증 결과와 배포 전 남은 외부 설정은 GitHub에 정리했습니다. 공개 출시와 실기기 검증이 끝났다고 주장하지 않습니다. 디자인 참고: Canva Pitch Deck 템플릿 목록과 미리캔버스 PPT 목록. 템플릿 자산을 내려받거나 복제하지 않고 앱 팔레트로 새 레이아웃을 작성했습니다.
