# 번역 지연 개선 · 2026-10-19

요청: 실제 원인 측정, 개선, 동일 조건 전후 속도 비교. 실기기/실제 마이크는 제외하고 이 프로젝트의 Mac 서버만 변경한다.

- [x] 앱/서버 경로 확인 및 단계별 시간 측정 도구 작성
- [x] 기존 설정: 12개 합성 문장, warm 100회, cold 3회, 요약 모델 전환 뒤 3회, 동시 10요청
- [x] 불필요한 모델 재로딩 방지 회귀 RED→GREEN (모델·프롬프트·번역문 캐시 변경 없음)
- [x] 동일 조건 개선 후 측정, 결과 텍스트 비교, 실제 회원 HTTPS 요청 검증
- [x] 현재 프로젝트 서버에 적용, 문서·원자료·README 갱신
- [ ] 최종 커밋 GitHub push 확인

측정 정의: loopback HTTP 완료 응답 시간과 Ollama load/prompt/eval 시간. 앱 렌더링·STT·TTS·실기기 왕복은 별도다. cold는 runner unload이며 OS 디스크 캐시 초기화를 뜻하지 않는다. 100회 요청은 12문장의 반복이며 일반 번역 품질 평가가 아니다. 동시 요청의 429를 성공 응답 지연 분포에 섞지 않는다.

결과: [성능 보고서](../docs/TRANSLATION_PERFORMANCE.md). 요약 전환 뒤 n=3 평균 55.3% 감소, warm n=100 평균 변화 없음. 첫 전환 재로딩 한계 유지. 자동 TTS 설정·동기화 구현, Node108/Android114/iOS120 PASS, 13장 발표자료에 최종 모델 역할·선정 이유 추가. 사용자 요청으로 발표자료의 비교·개선 전후 수치는 제거하고 개발 문서에만 보관.
