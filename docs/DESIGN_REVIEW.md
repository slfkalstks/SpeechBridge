# 설계 반대 검토

> 아래 초기 상용 API 언급은 변경 전 검토 이력이다. 현재는 유료 사용 금지이며 무료 로컬 연결 검토는 문서 끝에 추가했다.

검토일: 2026-10-17. 대상: `docs/PRODUCT.md`, `plans/app-foundation.md`, 현재 KMP 템플릿 설정. ECC blueprint의 별도 검토 단계로 수행했다. 앱 코드는 변경하지 않았다.

판정: 번역/기록 독립 선택과 수동 입력 우선 접근은 사용자 요구와 일치한다. 아래 High 항목을 설계에 반영한 뒤 구현한다. 음성·실기기·유료 API 실측은 후속으로 유지하며, API 적합성과 실시간 성능이 검증되었다고 표현하지 않는다.

## High — 구현 전에 고정할 규칙

### R1. 종료한 기록 처리와 응답 무효화가 충돌

제품은 기록 화면에서 재번역/정리를 허용하지만, 현재 불변 규칙은 세션 종료 뒤 모든 응답을 무시한다. 또한 같은 revision에서 반복 요청한 응답 순서가 뒤바뀌거나 정리 도중 다른 발언이 바뀌는 경우가 명시되지 않았다.

조치: 요청마다 session ID, 작업 generation/request ID, 대상 언어와 근거 revision snapshot을 캡처한다. 새 요청/수정/삭제/종료 전환은 해당 요청을 무효화한다. 종료한 기록에서 새로 시작한 요청은 허용한다. 정리 요청은 전체 입력 snapshot이 여전히 일치할 때만 반영한다. 같은 근거 revision의 중복 요청은 최신 요청만 적용하며 반복 정리로 사용자 검토 항목을 덮어쓰지 않는다.

검증: 요청 A/B 역순 완료, A 진행 중 원문 변경, 삭제 후 완료, 종료 전 요청 완료, 종료 후 새 요청, 정리 입력 중 한 발언 수정.

### R2. 항목 수정과 근거 재검토 상태를 분리해야 함

원문 수정에 대한 reviewed 해제는 있지만, 항목의 내용/담당자/기한 수정 시 규칙이 없다. 완료 항목을 단순히 done으로 유지하면 할 일 목록에서 재검토가 숨겨질 수 있다.

조치: 항목 편집도 검토를 해제한다. sourceRevision은 근거를 다시 확인하는 명시적 검토 동작에서 갱신한다. 완료 항목도 근거/항목 수정 후에는 검토 대기에서 보이고, 미검토 상태의 할 일 등록·완료를 도메인에서 거부한다. 과거 완료 사실은 필요하면 별도 필드로 보존하되 현재 확정 상태와 혼동하지 않는다. 사용자 편집 내용과 모델 재추출 결과는 별도 초안으로 유지한다.

검증: 검토→항목 편집→완료 거부, 완료→원문 수정→재검토 노출, 재추출이 수동 편집을 덮어쓰지 않음.

### R3. 저장 오류와 손상 복구에 데이터 손실 방지가 필요

오류 알림만으로는 로딩 실패 후 빈 상태를 정상 저장하여 기존 파일을 지우거나, 비동기 쓰기 순서가 뒤집혀 삭제한 기록이 복원될 수 있다.

조치: 로드 결과를 absent/success/corrupt/unsupportedVersion/readFailure로 구별한다. 실패 시 자동 저장을 잠그고 원본을 보존한다. 쓰기를 직렬화하고 플랫폼별 원자적 교체를 사용한다. 쓰기 실패 시 메모리 내용과 미저장 상태를 유지하며 재시도를 제공한다. 삭제 성공은 저장 결과에 맞춰 알린다. UI 스레드에서 디스크 작업을 하지 않는다.

검증: 손상 파일·미지원 버전을 덮어쓰지 않음, 저장 실패 재시도, 빠른 연속 수정/삭제의 최종 스냅샷, 재시작 복원.

### R4. 기록 off의 범위와 생명주기 명확화

기록 off 데이터의 저장 제외는 적절하다. 그러나 할 일 목록/화면 상태 복원/종료 세션 보관을 통해 우회 저장되거나 메모리에 계속 남을 수 있다.

조치: 세션 설정은 시작 후 불변으로 두거나 전환 규칙을 명시한다. 세션과 연결 항목을 하나의 저장 단위로 필터링한다. off 세션·입력 초안·토큰에는 저장 가능한 UI 상태를 사용하지 않는다. 종료/새 세션 시작 시 off 세션 데이터와 파생 항목을 제거한다. off 세션에서는 영구 할 일 등록이 불가능함을 UI에서 설명한다. 기록 off는 앱 기기 내 저장을 뜻하며, 외부 API 전송/제공자 보존 정책까지 없다는 뜻으로 표시하지 않는다.

검증: off 세션의 발언·항목·초안·토큰이 저장 payload에 없음, 종료 후 비노출, 재시작 후 비노출.

### R5. API 자격증명과 개발 연결 경로 보완

현재 `.gitignore`에는 `.env` 제외가 없고 Android manifest에는 INTERNET 권한이 없다. 서버가 127.0.0.1에 바인딩하면 Android 에뮬레이터의 localhost는 서버를 가리키지 않는다. HTTP 개발 예외가 없으면 실제 연결 준비가 작동하지 않을 수 있다.

조치: `.env`/환경별 비밀 파일을 제외하고 `.env.example`만 추적한다. 접속 토큰 미설정 시 서버의 유료 경로는 fail closed 한다. Android INTERNET 권한과 debug 범위의 명확한 로컬 네트워크 설정을 준비하고, iOS ATS 정책도 검증한다. 개발 가이드에는 Android `adb reverse` 경로와 iOS 시뮬레이터 루프백 경로를 분리한다. 인증 헤더를 다른 호스트로 보내는 redirect를 허용하지 않는다. 사용자 입력 서버 URL은 http(s)만 허용하고 로컬 개발 외에는 HTTPS만 사용한다. 토큰/요청 원문/상위 서비스 오류 원문을 로그나 UI 오류에 노출하지 않는다.

검증: 인증 미설정·불일치 401/503, redirect 거부, 환경 파일 제외, 네트워크 권한/개발 URL 설명. 실제 유료 호출은 키 설정 전 미검증으로 남긴다.

## Medium — 구현·인계에 반영

### R6. 서비스 준비와 실제 연결 성공을 구분

`/health`에서 환경 변수 존재만 확인한 상태를 '연결 성공'으로 표시하면 잘못된 키·지역·모델 접근 실패를 숨긴다. 키 존재는 '서버 설정됨', 유료 요청의 성공은 '해당 요청 성공'으로 구분한다. 서비스별 준비 상태, 입력 보존, 명시적 재시도를 제공한다. timeout 후 무제한 재시도하지 않는다.

### R7. API 선정은 유효한 후보이며 음성 성능·지원은 후속 확인

Azure Speech/Translator와 구조화 추출의 역할 분리는 타당하다. 다만 SDK 사용 가능성과 한국어/영어/일본어 조합에서 목표 지연·정확도 달성은 별개다. 실제 계정에서 모델 ID 접근, 지역별 음성 기능/voice, 언어별 응답과 Speech 토큰 만료 갱신을 추후 확인한다. '연결 준비' 범위에는 네이티브 음성 이벤트/에러/취소 계약을 포함하되 실제 녹음 성공 상태를 표시하지 않는다.

### R8. 개인정보 저장 위치와 백업 정책

Android 템플릿은 `allowBackup=true`다. '기기에 저장'이 기기 밖 백업 여부까지 약속하는 문구가 되지 않도록 저장 위치·OS 백업 정책을 명시한다. 이 과제의 대화 데이터는 플랫폼 앱 전용 저장소를 사용하고, 원하지 않는 OS 백업은 플랫폼 설정으로 제외한다. 서버는 캐시 금지 헤더와 요청 본문 비로깅 정책을 적용한다.

## 조치 기록

주 구현 에이전트가 각 R 번호에 대해 설계 반영 위치, 테스트 결과, 남은 미검증 사항을 이어서 기록한다. 현재 문서는 사전 검토이며 구현 검증 통과를 의미하지 않는다.

### 구현 전 반영 완료

R1–R3은 PRODUCT의 상태·저장 규칙에 반영했다. R4–R6 및 R8은 마지막 세부 규칙에 반영했다. R7은 음성 어댑터 계약과 후속 실측으로 분리했다. 사전 중대 설계 지적은 해결했으며, 아래 규칙의 실제 이행은 구현 테스트에서 확인한다.

### 첫 구현 검증 결과

R1–R8의 코드 반영·테스트·남은 검증은 [VALIDATION.md](VALIDATION.md)의 조치 표에 기록했다. 핵심 공통 테스트 14개와 서버 테스트 11개 통과. 실제 API·음성 성능은 미검증이다.


## 무료 로컬 provider 후속 검토 — 2026-10-17

ECC blueprint에 따라 별도 검토 에이전트가 계획과 실제 구현을 검토했다. 주요 지적과 조치:

- 클라이언트 중단이 추론을 계속 소비함 → HTTP 연결 종료·앱 취소·90초 deadline을 상위 fetch와 대기열에 전파. 취소/timeout/slot 해제 테스트.
- 긴 입력의 조용한 잘림 → 번역 문장 분할·단일 문장 초과 거부, 추출 보수적 context 예산, 완료 이유가 stop이 아니면 실패.
- 이름만 로컬인 cloud alias → loopback origin·승인 태그·tags/show의 로컬 모델 메타데이터 검사, redirect 거부.
- 조작된 AI 근거 → 정확한 ID/revision/원문 인용문 검사, 미기재 담당자·기한 제거. 의미 검토는 사용자가 수행.
- 후속 발언에서 취소된 요청의 기존 항목 잔류 → 전체 대화 revision snapshot으로 재검토 전환, 새 추출에 없는 이전 항목 경고, 원본/사용자 편집은 보존. 대화 전체를 검토창에 표시. 새 담당자 결과는 별도 초안.

후속 재검토에서 남은 High 지적은 보고되지 않았다. 검토 자체는 실행 테스트가 아니며 주 에이전트의 자동 검사·실측·UI 확인은 VALIDATION/LOCAL_AI_RESULTS에 구분했다. JSON mode로의 출력 변경도 형식/근거 검증을 통과해야 반영한다.
