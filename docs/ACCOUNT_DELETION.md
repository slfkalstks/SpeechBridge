# 계정 삭제 구현과 남은 연결

2026-10-18. 서버 API와 PostgreSQL 삭제·복원 보호를 구현하고 가상 계정으로 검증했다. **앱 삭제 화면, 기기 대기함 정리, 외부 웹 요청 경로까지 완성된 상태는 아니다.** 현재 시연 앱과 시연 계정은 유지한다.

## 공식 배포 요구 확인

Apple은 계정 생성 기능이 있는 앱에서 계정 삭제를 시작할 수 있어야 하며, 계정과 관련 데이터를 삭제하는 흐름을 요구한다. 비밀번호 등 재확인 단계는 허용한다. [Apple 계정 삭제 안내](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)

Google Play는 앱 안의 삭제 경로와 앱 밖에서 삭제 요청을 시작할 수 있는 웹 경로를 요구한다. 현재 프로젝트에는 외부 공개 HTTPS 주소가 없으므로, 웹 구현과 실제 게시 주소 확보를 구분한다. [Google Play 계정 삭제 요구](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko)

## 구현된 계약

`POST /auth/delete`는 회원 Bearer 세션과 JSON의 `username`, `password`, `confirm: true`를 요구한다. 로그인한 계정의 아이디가 일치해야 하며, 현재 비밀번호를 다시 확인한다. 인증 경로의 요청 크기·시도 횟수 제한을 적용한다. 단순 로그아웃이나 요청 본문의 다른 사용자 ID로 삭제할 수 없다.

사용자 행 잠금과 트랜잭션 안에서 비밀번호·현재 세션 만료/폐기를 재확인하고, 복원 방지 영수증을 남긴 다음 사용자 행과 외래 키로 연결된 데이터를 삭제한다. 모든 세션이 함께 폐기된다. 응답을 잃은 경우 원래 삭제 요청의 토큰 해시와 아이디 해시로 성공 여부를 재확인하므로, 같은 아이디로 새로 만든 계정을 지우지 않는다. 삭제와 동시에 시작했던 로그인은 계정 행을 다시 확인하여 새 세션을 발급하지 못한다.

마이그레이션007의 `account_deletions`는 사용자 ID·아이디·삭제 요청 토큰의 SHA-256과 삭제 시각만 보관한다. 원문·비밀번호·원시 토큰을 저장하지 않는다. 일반 데이터 역할은 접근할 수 없고, 인증 역할도 이 영수증을 수정·삭제할 수 없다. 해시도 삭제 처리 목적의 기록이므로 향후 개인정보 안내에 보관 목적을 명시해야 한다.

## 백업과 이전 데이터

- 복원 시 원본 DB의 최신 삭제 영수증을 읽고, 백업 검증 후 최신 스키마를 적용한 다음 삭제 대상 계정·기록을 복원 사본에서 제거한다. 원본 DB의 삭제 영수증을 확인할 수 없으면 복원을 실패 처리한다.
- 복원 도중·이후에도 삭제가 추가될 수 있다. 따라서 복원 결과는 `activationRequired: true`이며, 현재 API는 `speechbridge_restore_*` DB로 바로 시작할 수 없다. `.env`의 DB 이름만 바꾸는 수동 전환을 금지한다. 운영 전환 시 쓰기 중단·마지막 삭제 이력 반영·검증·명시적 활성화를 수행하는 후속 도구가 필요하다.
- 예전 SQLite 가져오기도 삭제 영수증을 확인해 계정을 다시 만들지 않는다. 기존 SQLite 원본은 변경하지 않는다.
- 기존 dump·SQLite 보존본 자체에서 개인 데이터가 즉시 제거되는 것은 아니다. 백업 보존 기간과 만료 삭제, 예전 보존본 정리 정책을 구현하고 사용자에게 설명하기 전에는 계정 삭제 전체 기능이나 스토어 제출 준비 완료로 표시하지 않는다.

## 검증과 다음 작업

테스트는 프로젝트의 별도 `speechbridge_test` DB에서 생성한 가상 계정만 사용한다. 13개 사용자 데이터 테이블에 실제 행이 있는지 확인한 뒤 모두 삭제되는지 검사했다. 다른 회원 보존, 잘못된 비밀번호/확인/세션 거부, 로그아웃과 삭제 경합, 삭제 중 로그인 발급 차단, 회원 HTTP 응답, 삭제 전 백업 복원, 예전 SQLite 재가져오기를 확인했다. 전체 서버 테스트98개 통과. 실제 사용자나 시연 계정을 삭제하지 않았다.

이어 구현할 내용:

1. 앱의 삭제 확인·비밀번호 재입력, 진행 중 입력·녹음 중단, 계정별 암호화 대기함만 제거, 보안 저장 실패·앱 종료 후 정리 재개.
2. 다른 기기에도 삭제 완료를 구분해 알릴 수 있는 세션 폐기 확인 계약. 일반 만료와 계정 삭제를 혼동해 대기 내용을 지우지 않도록 한다.
3. 백업·이전 보존본의 삭제 정책과 운영 복원 전환 절차.
4. 로그인·재확인을 거친 웹 삭제 경로와 운영 URL, 개인정보 안내.
5. 앱·웹 통합 검증 후 설치 파일 재빌드와 시연 서버 업데이트.
