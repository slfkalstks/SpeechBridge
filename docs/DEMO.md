# SpeechBridge 시연

현재 Mac 서버와 iPhone 시뮬레이터에서 시연하도록 준비했다. 회원 로그인, HTTPS, PostgreSQL 기록 저장, 종료 후 AI 제목·분류·요약, 결정 사항 추출을 실제 앱에서 확인했다. Android 설치 APK도 준비했다. 실제 휴대전화 마이크·청취 품질 검증과 스토어 배포 완료를 뜻하지 않는다.

[직접 앱 시연 검증 결과](DEMO_UI_VALIDATION.md): 언어 전환·실제 번역·요약·수동 수정·할 일 완료·필터·화면 모드·연결 복구·권한 거절 안내를 확인했다. 이번 검증으로 만든 `demo reviewed` 기록이 추가되어 현재 시연 계정에는 4개 기록이 있다.

## 바로 시작

프로젝트 루트 `SpeechBridge/`에서:

```sh
./Demo.command
```

Finder에서는 `Demo.command`를 더블클릭해도 된다. 실행 후 **Simulator → SpeechBridge**를 열면 된다. 현재 시뮬레이터에는 별도 시연 회원이 로그인되어 있다. 계정은 `.runtime/demo/account.json`에서 로컬로 확인한다. 비밀번호·토큰을 발표 화면이나 Git에 노출하지 않는다.

시작 명령은 이 프로젝트의 PostgreSQL·AI·API·HTTPS 서비스를 확인하고, 없는 서비스만 시작한다. 기존 계정과 기록을 초기화하지 않는다. 다른 프로젝트가 포트를 사용하면 중단하며 해당 프로세스를 종료하지 않는다. 같은 시연 계정을 재사용하고 수정·삭제한 예시를 덮어쓰거나 되살리지 않는다. 준비가 끝난 뒤에도 서버는 실행 상태를 유지한다.

| 준비물 | 위치 / 상태 |
|---|---|
| Android Debug APK | `.runtime/demo/SpeechBridge-demo.apk` |
| iOS 시뮬레이터 앱 | `.runtime/xcode-derived/Build/Products/Debug-iphonesimulator/SpeechBridge.app` |
| 빌드 주소·인증서·SHA-256 | `.runtime/demo/build.json` |
| 최근 서버 점검 결과 | `.runtime/demo/readiness.json` |
| 서버 상태만 확인 | `npm --prefix server run demo:check` |
| 서버만 준비 | `npm --prefix server run demo:start` |
| 두 플랫폼 시연 빌드 다시 생성 | `sh scripts/demo-build.sh` |

`readiness.json`의 모델 준비 표시는 모델 파일과 텍스트 런타임 확인이다. 음성 인식 정확도나 실제 녹음 성공 판정은 아니다. `Demo.command`는 빌드 주소·CA 지문과 파일 해시를 확인하므로 다른 주소나 빌드가 섞이면 재빌드를 안내한다.

## 5분 진행 순서

| 시간 | 앱에서 할 일 | 설명할 내용 |
|---|---|---|
| 0:00–0:40 | 대화 탭의 마이크·언어쌍·맞바꾸기 표시 | 음성 입력 중심, 한국어·영어·일본어, 키보드는 보조 |
| 0:40–1:40 | 실제 마이크 테스트가 가능한 경우 `눌러서 말하기` → 허용 → 한 문장 → 완료 | 말한 내용의 언어 감지·기록·번역. 한 발화 최대30초, 녹음 완료 후 처리 |
| 1:40–2:40 | 대화 종료 → 기록에서 요약 확인 | 처음 종료할 때 제목·일상/업무 분류·요약을 서버 AI가 작성. 이후 직접 수정 |
| 2:40–3:30 | 기록 목록에서 일상/업무, 업무 분류와 `시연 프로젝트` 폴더 확인 | 예시 기록으로 필터·분류·수동 수정 설명 |
| 3:30–4:20 | 할 일 → `발표 자료 준비` 완료 체크. AI 추출 항목의 근거 확인 | 수동 예시와 실제 AI 추출 항목을 구분하고, AI 후보는 근거 검토 후 확정 |
| 4:20–5:00 | 설정 → 가로로 나열된 기기·라이트·다크 아이콘, 저장 상태 확인 | 계정별 DB 저장과 화면 모드 변경 |

음성 테스트를 보류한 자리에서는 준비된 기록과 키보드 보조 입력으로 위 흐름을 시연한다. **이때 음성 인식 시연이라고 설명하지 않는다.** 보조 입력 예문은 `팀 회의에서 금요일 출시를 확정했습니다.`다. 실제 시뮬레이터 검증에서는 `금요일 출시 확정`이라는 제목, 업무·회의 분류, 요약과 결정 후보가 생성됐다. 모델 응답은 매번 달라질 수 있다.

최초 예시 세트는 일상 기록1개, 업무 기록1개와 할 일1개, 종료 자동 정리를 보여줄 진행 중 대화1개다. 미리 입력한 번역·요약·할 일은 **시연용 수동 예시**다. 검증 과정에서 진행 중 대화는 실제 AI 정리를 마쳤다. 다시 자동 정리를 시연하려면 새 대화를 시작한다. 기존 기록을 강제로 초기화하지 않는다.

## 마이크와 실패 상황

- 시뮬레이터의 과거 SpeechBridge 마이크 거부 상태를 초기화했다. 다음 마이크 사용 때 직접 권한을 선택한다. Mac 또는 시뮬레이터가 추가 권한을 요청하면 사용자 판단으로 허용한다. 임의 녹음은 수행하지 않았다.
- 인식·번역 중에는 완료를 기다린다. Mac은 여러 AI 모델을 공유하므로 다른 모델 작업이나 대규모 빌드를 동시에 실행하지 않는 편이 시연에 유리하다. 지연이 일정하다고 보장하지 않는다.
- 저장 대기·실패가 보이면 새 입력을 반복하지 말고 연결을 확인한다. 전송 대기 내용은 기기에 암호화 보관되며, 서버 수신 확인 후 제거된다. 원시 녹음의 앱 종료 후 복구는 아직 지원하지 않는다.
- 이름·호명·고유명사 오류가 확인된 적이 있다. 중요한 번역과 AI 후보는 원문과 비교하고 수정한다.

## Android 휴대전화

현재 빌드는 Android15/API35 이상이 필요하다. Mac과 휴대전화를 같은 Wi-Fi에 연결하고 Mac을 깨어 있는 상태로 유지한다. API·DB·AI는 내부 연결을 유지하고, 시연 앱은 프로젝트 HTTPS 프록시에 연결한다. 일반 사용자는 서버 주소나 토큰을 앱 설정에 입력하지 않는다.

USB 디버깅을 켠 테스트 기기가 연결되면 Android SDK의 `adb devices`에서 대상 기기를 확인하고:

```sh
adb -s DEVICE_SERIAL install -r .runtime/demo/SpeechBridge-demo.apk
```

여러 기기가 있을 수 있으므로 대상 serial을 명시한다. 실제 기기 설치·녹음 검증은 아직 수행하지 않았다. 시스템 인증서 저장소에 CA를 설치할 필요는 없다. 공개 CA는 해당 Debug 앱에만 포함된다.

## iPhone 휴대전화와 네트워크 변경

iOS 시뮬레이터 앱은 실제 iPhone 설치 파일이 아니다. 실제 iPhone에는 Xcode의 개발 팀 서명·프로비저닝이 필요하며, 현재 `iosApp/Configuration/Config.xcconfig`의 `TEAM_ID`는 비어 있다. Apple 개발 계정 선택과 연결 기기 확인 후 기기용 Debug 빌드를 진행해야 한다.

Mac의 Wi-Fi/IP가 바뀌었거나 인증서가 갱신되면 `sh scripts/demo-build.sh`로 주소와 인증서를 반영하고 새 APK/시뮬레이터 앱을 설치한다. 이전 HTTPS 프로세스가 다른 인터페이스에 남아 있으면 시작 명령이 중단한다. 이 경우 `.runtime/demo/https.pid` 또는 포트8443의 프로세스 작업 폴더를 확인하고 **이 프로젝트의 프록시만** 종료한 뒤 다시 실행한다. 다른 프로세스를 강제로 정리하지 않는다.

시연용 CA는 공개 배포용 인증서가 아니다. Release 빌드에는 `speechbridge.localTls=true`를 사용할 수 없다. 실제 외부 공개 배포에는 운영 HTTPS 주소와 배포 설정을 별도로 확정해야 한다.
