# 인증된 로컬 음성 API 검증

2026-10-17. V2 구현 후 기존 가상 문장 WAV를 HTTP로 전사하고 같은 가상 문장을 HTTP로 합성했다. 사용자 마이크와 모바일 앱은 사용하지 않았다. 엔진/모델 버전은 [첫 엔진 실측](LOCAL_VOICE_RESULTS.md)과 동일하다.

## 실제 실행 결과

| 언어 | STT HTTP 완료 | TTS HTTP 완료 | 반환 음성 길이 |
|---|---:|---:|---:|
| 한국어 | 0.316초 | 4.173초 | 4.960초 |
| 영어 | 0.279초 | 2.991초 | 4.560초 |
| 일본어 | 0.267초 | 3.246초 | 5.280초 |

각 요청마다 새 자식 프로세스에서 모델을 로드했다. HTTP 전송·프로세스 시작·로딩·추론·응답 수신을 포함한 한 번의 관측이다. 이전 실행의 OS/Metal 캐시 영향을 분리하지 않았으며 콜드 스타트·평균·p95·실시간 스트리밍 수치가 아니다. Ollama는 꺼져 있었고 텍스트 모델과 동시에 추론하지 않았다.

STT 출력은 이전 파일 전사 결과와 동일했다. 일본어 입력의 `ユキさん`이 `由さん`으로 인식되는 오류가 재현됐다. API 성공은 정확도나 청취 품질 보장이 아니며 앱의 확인/수정 단계가 필요하다.

실제 TTS 프로세스를 시작한 뒤 300ms에 클라이언트 요청을 취소했다. 취소부터 프로세스 `close`까지 약3.2ms, 이후 영어 STT 요청 성공, 남은 요청 임시 폴더0개를 확인했다. 이는 모델 시작 구간의 취소 검증이다. SIGTERM을 무시하는 테스트 프로세스에는 SIGKILL을 보내고 PID가 사라진 후 반환함을 별도로 검사했다. 추론 중 모든 시점의 취소 지연 분포는 측정하지 않았다.

원자료: [local-voice-api.json](validation/local-voice-api.json). 합성 출력은 로컬 `.runtime/voice/api-fixtures/`에 보존한다. 실제 요청 음성은 `.runtime/voice/requests/request-<pid>-<random>/`에서 처리 후 삭제한다.

## 재현

모델과 기존 합성 샘플이 준비된 Mac에서 앱 루트 기준:

```sh
node server/evaluate-voice-api.mjs
```

스크립트는 메모리에서 임의 토큰을 만들고 빈 loopback 포트에 임시 API를 연다. 기존 토큰 파일을 읽거나 출력하지 않는다. 완료·실패 시 API를 종료한다. 이 환경에서는 제한된 실행의 엔진 호출이 실패했고, 승인된 샌드박스 외부 실행에서 성공했다. 프로세스 stderr는 원문 노출 방지를 위해 폐기하므로 최초 실패의 내부 엔진 원인까지 확정하지 않았다.

자동 검사는 `cd server && npm test`. 현재34개가 통과했다. 기존18개와 음성16개로, 인증·형식·크기·언어·무음·잘못된 모델 출력·timeout·중복/혼합 요청·클라이언트 종료·SIGKILL·늦은 응답·서버 종료·임시 파일 권한/정리를 확인한다. HTTP 실패/동시 요청 검사는 모의 엔진 또는 테스트 자식 프로세스이며 위 실제 모델 실측과 구분한다.

## 남은 범위

V3 모바일 마이크/재생·권한·상태기계, V4 음성→번역→음성 통합 측정은 아직 미구현이다. 사람 음성·청취 품질·소음·여러 화자·실기기·네트워크·텍스트 모델 혼합 메모리·장시간 부하·프로세스 강제 크래시 복구 검증도 남아 있다. PCM RMS≤16의 매우 작은 입력을 거르는 검사는 음성 활동 감지(VAD)가 아니므로 배경 소음을 발화와 구분하지 않는다.
