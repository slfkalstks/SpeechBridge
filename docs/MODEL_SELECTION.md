# 사용 모델과 선정 근거

2026-10-19 기준. 모든 추론은 현재 Mac에서 실행한다. 유료 API·Gemini 연동·휴대전화 LLM 설치는 없다. 모델을 자체 학습한 것이 아니라 공개 가중치를 로컬 런타임으로 실행한다. 아래 선정은 이 앱의 한국어·영어·일본어와 현재 Mac 조건에 대한 판단이며, 모든 후보 중 최고라는 결론은 아니다.

| 역할 | 실제 사용 모델 / 실행 방식 | 선정 이유와 확인 범위 |
|---|---|---|
| 음성 → 원문 | Nemotron 3.5 ASR Streaming 0.6B, Q8 GGUF / NeMo-Speech.cpp 0.2.0 Metal | Mac에서 실행 가능한 런타임, 한·영·일 자동 언어 감지와 파일 전사를 합성 샘플로 확인 |
| 원문 → 번역 | TranslateGemma 12B, Q4_K_M / Ollama | 비교한 4B보다 느리지만 소수 시험 문장에서 수량·부정·이름 등 의미를 더 잘 보존 |
| 제목·분류·요약·할 일 후보 | Gemma 4 12B IT QAT / Ollama JSON mode | 구조화 결과를 서버에서 검증할 수 있고, 비교한 Qwen의 영·일 추출 요청보다 빠른 실측 |
| 번역 → 음성 | Qwen3-TTS-12Hz-0.6B-CustomVoice, MLX bf16 변환본 / mlx-audio | 한·영·일 지원, Apple Silicon 로컬 실행, 고정 음색으로 합성 가능. 사용자 음성 복제는 필요하지 않음 |

`B`는 모델 이름의 규모 표기(십억 단위)다. Q4_K_M과 Q8은 양자화된 배포 형식, QAT는 양자화를 고려한 학습 계열 표기, bf16은 수치 형식이다. 이름의 숫자를 다운로드 용량이나 실제 전체 메모리 사용량으로 해석하면 안 된다. STT 모델 이름에 Streaming이 있지만 **현재 앱은 녹음 완료 후 WAV를 전송**한다. TTS도 완성된 WAV를 받아 재생하며 스트리밍 통역을 구현했다고 주장하지 않는다.

## 번역: 왜 빠른 4B 대신 12B인가

2026-10-17 M3 Max·36GiB에서 6방향의 짧은 합성 문장을 비교했다. 로딩 뒤 서로 다른 문장 응답은 12B 0.803–1.056초, 4B 0.304–0.414초였다. 4B는 더 빨랐지만 ‘보고서 두 부’를 ‘both reports’로 바꾸거나 Yuki를 ‘つきよさん’으로 바꾸고, 원문에 없는 알레르기 이유를 보탰다. 12B는 이 예제들의 수량·시각·부정·이름을 보존했다. 업무 요청을 기록하는 앱에서는 빠르게 잘못 전달하는 것보다 의미 보존이 중요하므로 12B를 기준으로 삼았다.

이는 작은 예제의 의미 대조다. 원어민 평가나 통계적 정확도 평가가 아니며, 후속 음성 경로에서는 호명·고유명사 문제가 남아 있다. [비교 결과와 원자료](LOCAL_AI_RESULTS.md)를 함께 제시한다.

## 정리: 왜 Gemma 4인가

같은 명시적 요청을 Gemma 4 12B IT QAT와 Qwen3.5 9B Q8로 비교했다. 로딩 뒤 영어/일본어 추출은 Gemma **2.536 / 2.603초**, Qwen **3.899 / 4.558초**였다. 두 모델 모두 명시 요청을 추출하고 후속 취소·잡담·교육용 인용 사례에서는 빈 결과를 반환했다. 이 조건에서 Gemma의 추출 속도와 JSON 출력이 앱에 적합했다.

다만 위 속도는 **추출** 시험이며 모든 요약·분류 작업에서 우수함을 증명하지 않는다. 항목 없는 사례는 Qwen이 더 빨랐다. 서버는 ID·revision·원문 인용을 검증하고, 사용자가 근거를 확인한 뒤 할 일로 등록한다. 모델은 최초 제목·분류·요약을 생성하며 이후 수동 편집을 덮어쓰지 않는다.

## 음성: 왜 Nemotron과 Qwen3-TTS인가

Nemotron은 필요한 언어와 Mac Metal 실행 경로가 있으며 고정 버전 모델·런타임을 실제 설치해 전사했다. 최신 회원 API의 합성 3언어 샘플에서 STT는 약 335–520ms였다. 일본어 `ユキ`가 `由`로 바뀐 사례가 있으므로 정확도 보장은 없다. Whisper 등과 동일 조건 비교를 하지 않았으므로 가장 정확하거나 빠른 STT라고 말하지 않는다. [실제 엔진 결과](LOCAL_VOICE_RESULTS.md), [회원 음성 원자료](../server/validation/member-voice-flow.json), [NVIDIA 모델 카드](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b), [Mac 런타임 설치 문서](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/v0.2.0/docs/install.md).

Qwen3-TTS의 공식 지원 언어에 한국어·영어·일본어가 포함된다. 현재 Mac에서는 MLX 변환본으로 동작하며, 언어별 고정 음색을 사용한다. 0.6B 버전을 실제 실행해 유효한 PCM을 확인했으나 다른 크기·엔진과의 우열은 검증하지 않았다. 현재 회원 API는 요청마다 프로세스를 시작하므로 음성 준비에 수 초가 필요하다. 최신 한국어 한 문장에서는 WAV 완성까지 **6.33초**, 생성 음성 길이는 **3.6초**였다. 사람의 청취 품질과 실제 스피커 재생은 별도 미검증이다. [Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice), [고정 MLX 변환본](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-bf16/tree/6415d95f88be018ff9e46813119dc3bc12261328), [최신 합성 원자료](../.ecc/benchmarks/tts-member-https.json).

## 이번에 바뀐 것은 모델이 아니라 실행 정책

네 모델의 종류·크기·양자화는 유지했다. 번역 속도를 위해 더 작은 모델로 바꾸지 않았다. Ollama의 동시 상주 허용을 1→2개로 바꾸고, 번역 모델 유지 시간을 30분→만료 없이 유지 요청으로 바꿨다. API 시작 시 번역 모델을 미리 준비한다. 추론은 계속 한 번에 하나다. 메모리 압박·런타임 종료·스케줄링에 따라 재로딩은 여전히 가능하다.

요약 모델을 올린 뒤 번역하는 3회 시험 평균은 **4.42→1.98초(55.3% 감소)**였다. 이미 준비된 100회 번역 평균은 **1.66→1.67초**로 개선되지 않았다. 따라서 “모든 번역이 55% 빨라졌다”는 주장은 틀리다. [전후 측정과 한계](TRANSLATION_PERFORMANCE.md)를 참고한다.

## 발표에서 사용할 설명

> 휴대전화의 성능과 유료 API 비용에 의존하지 않도록 Mac에서 역할별 모델을 실행했습니다. 번역은 작은 모델의 의미 변형을 확인해 12B를 선택했고, 정리는 실제 추출 비교에서 빠른 Gemma를 선택했습니다. 음성 모델은 필요한 세 언어와 Mac 실행 경로를 확인한 기준선입니다. 이번 속도 개선은 모델을 낮추는 대신 재로딩을 줄였습니다. 합성·소수 문장 결과이며 실사용 음성 정확도 검증은 남아 있습니다.
