# 음성 연결과 테스트 준비

2026-10-18. 최신 목표는 모든 앱 기능 구현과 배포 직전 준비다. 이 문서는 음성 연결 체크포인트이며 전체 배포 준비 완료를 뜻하지 않는다.

## 구현

마이크를 눌러 시작하고 다시 눌러 완료한다. 최대 30초 뒤 자동으로 완료하며, 언어를 감지한 최종 문장을 자동 기록·번역한다. 한국어·영어·일본어를 지원한다. 감지 언어가 오른쪽 언어이면 방향을 바꾸고, 제3언어이면 입력 언어를 바꾼다. 가운데 교환 버튼과 수동 선택도 유지한다. 화자 판별·상시 청취·스트리밍 통역은 제공하지 않는다.

Android는 AudioRecord/AudioTrack, iOS는 AVAudioRecorder/AVAudioPlayer를 사용한다. 입력은 mono PCM16 16kHz, 출력은 mono PCM16 24kHz다. 번역 읽기는 녹음 중 시작할 수 없고, 녹음을 시작하면 재생을 취소한다. 화면 이탈·백그라운드·계정 전환·언어 변경·원문 수정 때 진행 작업을 취소한다. 권한 콜백과 늦은 HTTP 결과는 이전 작업에 반영하지 않는다. Activity 재생성 때 장치를 교체하고, 이전 작업 정리 후 다음 작업을 시작한다.

원음은 영구 기록하지 않는다. Android는 메모리에서 처리하고 iOS는 백업 제외·파일 보호가 적용된 앱 전용 캐시에서 처리한 뒤 삭제한다. 서버 임시 파일도 요청 종료 시 제거한다. 서버가 다른 AI 요청을 처리 중이면 같은 세션과 녹음으로 제한된 재시도를 한다. 네트워크 실패·앱 종료 후 음성 자체를 복원하는 기능은 없다. 인식된 텍스트는 기존 암호화 전송 대기함과 PostgreSQL 저장을 사용한다. 입력 중인 키보드 초안은 음성 기록으로 소비하지 않는다.

- iPhone 17 Pro / iOS 26.5 시뮬레이터에서 가상 회원 로그인, 새 마이크 화면, 시스템 권한 요청·사용 설명, 허용 안 함 이후 대화 화면 복귀, 로그아웃을 확인했다. 마이크는 허용하지 않았으며 실제 녹음/재생과 권한 거부 알림 문구의 시각 확인은 남아 있다. 가상 계정 삭제 전 활성 세션 0개 확인. 기존 기기 기록 가져오기는 실행하지 않았다.
- 실제 로컬 모델과 PostgreSQL 가상 회원을 사용하는 HTTP 검증에서 3언어 자동 감지, 음성 합성, 비회원 차단, 로그아웃 후 토큰 차단, 잔여 임시 폴더 0개 확인. [원자료](../server/validation/member-voice.json).

| 합성 입력 | 자동 감지 | STT HTTP | TTS HTTP | 생성 음성 길이 |
|---|---|---:|---:|---:|
| 한국어 | ko | 339ms | 5,610ms | 5.28초 |
| 영어 | en | 311ms | 3,138ms | 3.84초 |

각 언어 한 문장씩이며 프로세스 시작·모델 로드가 포함된다. 입력 길이·순서가 달라 언어별 성능 비교나 p95가 아니다. 일본어 고유명사 오류는 이전 샘플과 동일하게 남았다. 자동 언어 감지 성공을 정확한 전사·발음 품질로 해석하지 않는다.

## 번역·DB까지 연결한 합성 검증

[통합 원자료](../server/validation/member-voice-flow.json)에서 3건 모두 인식→번역→PostgreSQL 저장/재조회→번역 음성 파일 생성까지 완료했다. 원문·번역·revision의 DB 왕복 일치를 검사했다. 실제 마이크·앱 스피커 출력은 이 검증에 포함하지 않았다.

| 입력→번역 | STT | 번역 | TTS | DB 왕복 |
|---|---:|---:|---:|---|
| ko→en | 462ms | 6,265ms | 5,414ms | 일치 |
| en→ko | 20,370ms | 1,094ms | 5,469ms | 일치 |
| ja→ko | 522ms | 1,068ms | 4,038ms | 일치 |

이 실행 중 별도의 Xcode 빌드도 진행했다. 영어 STT가 20.37초 걸렸으나 원인을 분리 측정하지 않았으므로 모델 상주나 빌드 부하 때문이라고 단정하지 않는다. 파일 단독 결과보다 편차가 커 실제 기기 지연 목표를 충족했다고 볼 수 없다.

내용 검토에서는 한국어의 호명 “유키 씨”를 영어 번역이 수신자 “send Yuki”로 바꿨다. 일본어 고유명사 오류도 번역에 전달됐다. **통합 흐름 성공과 번역 정확도는 별개이며**, 호명·수신자 관계와 고유명사 사례를 후속 품질 평가에 추가해야 한다.

## 바로 실행할 서버 검증

모든 명령은 실제 Gradle 프로젝트인 `SpeechBridge/`에서 실행한다. `.runtime`에 프로젝트 PostgreSQL과 음성 모델이 설치되어 있어야 한다. 새 설치는 [PostgreSQL 안내](POSTGRES.md), [음성 모델 고정 버전](LOCAL_VOICE_RESULTS.md), [회원 서버](ACCOUNT_SERVER.md)를 따른다.

```sh
npm --prefix server run db:status
npm --prefix server run db:start       # 중단된 경우만
npm --prefix server run setup:accounts # 기존 설정을 덮어쓰지 않음
npm --prefix server run start:ai       # 별도 터미널, 기존 11435 서버가 없을 때
npm --prefix server run start:accounts # 별도 터미널, 기존 8787 서버가 없을 때
```

새 회원 설정은 `SPEECH_PROVIDER=local-process`다. 기존 설정은 같은 항목을 확인한다. 이 서버는 127.0.0.1에만 바인딩한다. 외부 서비스나 사용자 공용 토큰은 필요 없다.

```sh
npm --prefix server test
node server/evaluate-member-voice.mjs
node server/evaluate-member-voice.mjs --with-translation
```

두 평가 명령은 `speechbridge_test` DB만 허용하고 무작위 가상 회원을 생성·정리한다. 기존 합성 WAV만 사용한다. 두 번째 명령은 번역과 DB 저장/재조회까지 포함하며 로컬 Ollama가 필요하다. 토큰·비밀번호를 결과에 출력하지 않는다. 모델 검증 명령을 여러 개 동시에 실행하지 않는다.

## 기기에서 확인할 순서

1. 테스트 빌드 설치 후 회원가입/로그인한다. Android 에뮬레이터는 10.0.2.2:8787, iOS 시뮬레이터는 localhost:8787에 자동 접속한다. 시뮬레이터는 loopback HTTPS, 휴대전화는 LAN HTTPS 준비 후 다시 빌드한다. [시연 안내](DEMO.md)를 따른다.
2. 마이크를 눌러 권한 거부 시 녹음이 시작되지 않는지 확인한다. 기기 설정에서 허용한 뒤 다시 시작한다. 권한 상태는 현재 시뮬레이터 설정을 확인한다.
3. 한국어 한 문장을 말하고 완료한다. 원문·영어 번역·서버 저장을 확인한다. 영어로 말하면 영어→한국어로 바뀌는지 확인한다. 일본어도 반복한다. 이름·날짜·숫자는 원문과 대조한다.
4. 번역의 스피커 아이콘으로 듣고 정지한다. 재생 중 마이크 시작, 녹음 중 키보드·다른 탭 이동, 홈 화면 이동, 전화/오디오 중단을 확인한다.
5. 짧은 입력·무음·30초 자동 완료·권한 철회·네트워크 중단·AI 서버 busy·느린 응답·취소 직후 재시작을 확인한다. 취소한 결과가 나중에 기록되지 않아야 한다.
6. 키보드 초안을 남긴 상태로 음성을 입력해도 초안이 유지되는지, 대화 종료 후 제목·분류·요약과 할 일을 확인하고 수동 수정 가능한지 확인한다.
7. 재실행·다른 기기 로그인으로 PostgreSQL 기록을 재조회한다. 사용자별 기록이 섞이지 않아야 한다.

실제 사람 음성·소음·블루투스·통화 중단·스피커 음질·실기기 네트워크·장시간 동작은 아직 미검증이다. HTTPS 시연 빌드·AI 작업 복구·DB 복원 도구는 준비됐다. 최신 범위는 [배포 직전 검증](PRE_RELEASE.md)을 따른다.

## 2026-10-19 시뮬레이터 연결·음성 회귀

사용자가 느린 번역과 음성 실패를 보고했다. 설치 앱의 예전 LAN 주소와 현재 서버 주소의 불일치, 이어 Mac의 LAN 인터페이스 부재를 확인했다. 시뮬레이터 데모는 `https://127.0.0.1:8443`으로 고정하여 Wi-Fi 변화와 분리했다. origin이 바뀌므로 재로그인이 필요하며 이전 origin의 대기 내용은 임의로 옮기거나 지우지 않는다.

음성 HTTP 연결 실패는 `network_unavailable`로 구분해 안내한다. 기존 generic audio failure와 구분하는 회귀를 추가했다. 번역 모델 유지 시간은 5분에서 30분으로 늘리고 시연 시작 때 합성 인사 문장으로 준비한다. 요약 모델 전환·메모리 부족·첫 로딩 지연까지 사라지는 것은 아니다.

현재 합성 샘플 3언어 STT→번역→DB 왕복→TTS 재검사는 모두 성공했다. STT 335–520ms, 번역은 결과 JSON 참조, TTS 3.8–6.1초다. 소수의 합성 샘플이며 실기기 성능이 아니다. [원자료](../server/validation/member-voice-flow.json).

호명/수신자 의미 변화와 일본어 이름 오류는 여전히 알려진 모델 품질 한계다. 문장을 자동 치환해 숨기지 않았으며 원문 수정·재번역·근거 검토를 사용한다. 별도 [호명 평가](../server/validation/vocative-before.json)는 정해진 5문장에 대한 검사이며 일반 정확도 수치가 아니다.


## 2026-10-19 녹음 완료 이후 실패 조사

사용자가 오류 발생 시점을 ‘녹음 완료를 누른 뒤’로 확인했다. 당시 SpeechBridge 프로세스의 CoreAudio 로그에 입력 장치 소실과 Stop timeout이 남아 있었다. 이는 입력 경로 이상을 보여 주지만, 사용자에게 표시된 일반 오류와 직접 연결하는 앱 예외 로그는 없어서 근본 원인으로 확정하지 않는다.

실제 마이크 없이 Apple AVAudioFile로 만든 합성 PCM 파일을 검사했다. Apple의 JUNK/FLLR 메타데이터를 포함한 정상 파일은 기존 파서로도 읽혔으므로 ‘모든 iOS WAV가 호환되지 않는다’는 가설은 기각했다. 반면 손상 파일·잘못된 샘플레이트가 일반 예외로 끝나는 오류 분류 문제는 테스트 2개로 재현했다(RED `8bdff69`).

- 완료된 임시 파일은 AVAudioFile로 PCM16을 읽은 뒤 서버용 표준 WAV로 변환한다. 16kHz·모노·0.1–30초 제한을 확인하며 변환 후 샘플이 보존되는지 검사한다.
- 입력 장치 시작/예상치 못한 중단, 저장 공간/파일 보호, 파일 읽기, 샘플레이트, 빈/짧은 녹음, 길이 초과를 별도로 안내한다. 임시 파일 삭제와 취소 처리는 유지한다.
- iOS 파일 회귀 5개(정상 샘플 보존, 짧은 입력, 손상 파일, 다른 샘플레이트, 빈 파일/길이 초과)와 기존 테스트를 포함해 총 116개가 통과했다. 실제 녹음이나 청취를 수행한 결과가 아니다.

시뮬레이터에서 다시 확인할 때 `I/O → Audio Input → MacBook Pro 마이크`를 선택하고 녹음한다. 이 메뉴와 내장 마이크 항목의 존재는 UI에서 확인했으며 입력 설정 자체를 바꾸거나 마이크 권한을 새로 부여하지 않았다. 같은 현상이 계속되면 새 안내 문구로 입력·파일·연결 중 실패 단계를 구분한다. 실제 사용자 녹음의 재현·해결 여부는 여전히 미확인이다.

API 근거: [AVAudioRecorder.stop](https://developer.apple.com/documentation/avfaudio/avaudiorecorder/stop()), [AVAudioFile](https://developer.apple.com/documentation/avfaudio/avaudiofile). 로컬 Xcode SDK 헤더의 PCM 읽기/변환 및 파일 닫기 계약도 확인했다.

## 2026-10-19 자동 읽기와 설정

새로 입력된 문장의 번역 완료 시 자동 TTS를 요청한다. 설정 → **번역 자동 읽기**에서 끄며, 기본값은 켜짐이다. 설정은 계정별 PostgreSQL `user_settings.auto_read_translation`에 저장하고 오프라인이면 암호화 대기함으로 보낸다. migration 011은 기존 데이터를 유지한다. 구 클라이언트가 화면 모드만 저장해도 자동 읽기 값을 덮어쓰지 않는다.

과거 기록 조회·재번역은 자동 재생하지 않는다. 화면 이동, 백그라운드 전환, 새 녹음 시작, 끄기 이후 도착한 오래된 번역도 재생하지 않는다. 이미 녹음/합성/재생 중이면 자동 읽기로 끼어들지 않는다. 재생 대기열은 없고 건너뛴 결과는 수동 듣기를 사용할 수 있다. 음성 생성 중에는 ‘준비 중’과 취소, 재생 중에는 ‘중지’를 표시한다.

- Node 108개: 실제 테스트 PostgreSQL의 기본값·꺼짐 저장·다른 기기 조회·구 설정 호환·잘못된 타입 거절 포함.
- Android Host 114 / iOS Simulator 120개: 자동 읽기·중복/늦은 응답 방지·수동 듣기·오프라인 저장 복원·동기화 포함. 오디오 장치 fake를 사용한 상태 검증이다.
- 새 Debug APK와 signed simulator 빌드 성공. iOS 설정에서 끄기→재시작→꺼짐 복원 확인, 실제 서버 snapshot false 확인. 기존 기록 4개 보존, 최종 설정 켜짐으로 복원.
